PROJECT 15 — AUTONOMY GOVERNANCE POLICY

The service is done in an autonomous mode but in a way that is specific to the action. Reading disk usage, 
listing large directories and reading application logs are ACT-tier operations as they are read-only and have a small blast radius.
Restart the RAG API, vacuum journald, clear the package cache and rollback to a reversible RAG configuration are APPROVE-tier
operations. Each named action has to be approved for execution by the current platform on-call engineer. 
Changes to the firewall policy, deletion of a volume, stopping nginx, rotating production credentials or creating recurring cloud 
cost are SUGGEST-tier decisions that need explicit human approval or action.

The tool set is based upon the Rule of Two. An unsupervised agent can process untrusted telemetry and read operational data on 
a narrow scope but cannot get arbitrary outbound Internet access via HTTP, email or public-write. Any flow or step that involves 
any untrusted content, access to private data or external communication will have to pass through the human gate and destination 
allowlist.

All proposals, blocks, approvals, actions, verification results, identities and UTC timestamps are logged in the audit.log file. 
VERIFY rechecks the Service signal used under the service before resolving.

It's possible that autonomous remediation might have a maximum of 100 Gi in any single incident and/or could be estimated 
to have a cost of $100 or less per month. High-risk AI systems should have effective human oversight (EU) Regulation 2024/1689 Article 14). 
This policy contains Annex III high-risk rules that were checked on 2026-08-10, with the current EU timeline having 
the following low-risk rules: product embedded: 2028-08-02, Annex III: 2027-12-02. 
Ultimate responsibility is with the identified human operator.
